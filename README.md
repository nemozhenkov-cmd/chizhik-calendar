# Чижик · Календарь скидок

Самостоятельный PWA-календарь одного магазина. Покупатели без регистрации; управление через Supabase Auth и разрешённый UUID администратора. Фирменные цвета #FFD400/белый/чёрный, готовые маскоты из проекта сроков, логотип с птицей.

## Возможности

- «Сегодня» и «Календарь», месяц/неделя, весь опубликованный период заранее.
- Видова, 163В и 9:00–21:00 в шапке; цен, заказов, оплаты и вкладки магазинов нет.
- «Товар дня», дата, процент; скидка на первые 5 единиц, с шестой без скидки.
- Периоды-черновики, товары с фото, изменение, удаление, предпросмотр, атомарная публикация/снятие периода.
- Публикации не пересекаются; один товар дня на дату в периоде; сервер проверяет границы дат.
- Посещаемость за день/неделю/месяц, график по дням, CSV. Московское время, без аналитики товаров.
- Сохранение опубликованного календаря и фото офлайн. Первый вход требует сети. Сохранённые данные могут устареть; видна дата обновления.
- PWA с локально собранными зависимостями и шрифтами системы; CDN для JS не нужен.

## Локальный запуск

Node.js 22+, `npm ci`, `npm run dev`. Сборка: `npm run build`; результат `dist/`. Тесты: `npm test`. Браузерные проверки: `node tests/browser.mjs` с установленным Chromium; проверка сама запускает локальный сервер на 4173 (`npx playwright install chromium`).

Конфигурация содержит только общедоступный publishable key и legacy anon JWT для JWT-проверки Edge Function. Секретных service_role ключей и паролей в репозитории нет.

## Вход и первое наполнение

Админка: корень сайта + `?admin=1`.

1. В Supabase → Authentication → Users → Add user → Create new user создайте администратора со своей почтой и паролем. Пароль задаёт владелец, не храните его в репозитории.
2. Скопируйте UUID созданного пользователя и выполните в SQL Editor `insert into public.admins(user_id) values ('UUID');`.
3. Войдите в админку, создайте период, загрузите реальные фото и проценты скидок, сохраните.
4. Откройте «Предпросмотр», проверьте даты/упаковки, нажмите «Опубликовать период».

Создание аккаунта без записи в `admins` не даёт никаких прав. Открытой регистрации в интерфейсе нет. Даже если кто-то самостоятельно зарегистрируется через Auth API, ему доступны только опубликованные данные.

## Размещение

`dist/` можно разместить на любом HTTPS-хостинге статических файлов. Вход в админку использует пароль и не требует email redirect. Бесплатный GitHub Pages требует публичного репозитория в обычной учётной записи. Перевод репозитория в публичный и выпуск покупательской ссылки ожидают отдельного согласия владельца.

Для GitHub Pages: Settings → Pages → Deploy from a branch → main → /docs. В репозиторий включена готовая сборка в `docs/`; после изменений выполнить `npm run package` и сохранить обновлённую папку `docs/` в GitHub.

Если меняется домен сайта, добавьте его origin в `supabase/functions/visit/index.ts` и повторно разверните функцию. Настроенный origin: `https://nemozhenkov-cmd.github.io`.

## Как считаются посещения

Одна вкладка использует случайный идентификатор 30 минут. После этого создаётся новый визит. В другой вкладке может считаться ещё один визит. Это не уникальные люди. Дата и дедупликация вычисляются сервером по Москве. Raw IP не записывается в таблицу: используется HMAC с солью, меняющейся ежедневно. Счётчик ограничивает приём 100 визитами с одного IP в сутки, поэтому общий IP мобильного оператора может приводить к недосчёту. Боты, блокировщики и отсутствие сети также влияют. После первого входа администратора устройство исключено из счётчика локальным маркером; очистка данных браузера сбрасывает маркер. Переход по ссылке «Сайт покупателя» из админки исключён из учёта.

RLS запрещает покупателю читать статистику, список администраторов и черновики или менять данные. Функция `visit` проходит JWT-проверку шлюза, проверяет origin и формат запроса, а записывает только визиты. Фото находятся в публичном bucket: сами адреса фото не являются секретом, в том числе фото черновиков. Не загружайте приватные документы.

## Эксплуатация

Сохраняйте резервную копию исходников и периодически экспортируйте таблицы в Supabase. Бесплатный тариф Supabase имеет квоты и может приостанавливать неактивные проекты. Доступность в российских мобильных сетях и при «белых списках» не гарантирована. Проверьте реальный адрес на Wi-Fi и мобильной связи перед печатью QR.

Оригинальные изображения товаров не перерисовываются: загрузка только уменьшает фото до 1000 px и сохраняет WebP. Демонстрационный `brand/sample-tan.jpg` — исходное изображение из каталога X5, используется только в локальных тестах, не публикует акцию.
