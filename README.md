# Чижик · Календарь скидок

Самостоятельный PWA-календарь одного магазина. Покупатели без регистрации; управление через Supabase Auth и разрешённый UUID администратора. Фирменные цвета #FFD400/белый/чёрный, готовые маскоты из проекта сроков, логотип с птицей.

## Возможности

- «Сегодня» и «Календарь», месяц/неделя, весь опубликованный период заранее.
- Без привязки к адресу магазина; цен, заказов, оплаты и вкладки магазинов нет.
- «Товар дня», дата, процент; скидка на первые 5 единиц, с шестой без скидки.
- Периоды-черновики, товары с фото, изменение, удаление, предпросмотр, атомарная публикация/снятие периода.
- Публикации не пересекаются; один товар дня на дату в периоде; сервер проверяет границы дат.
- Посещаемость за день/неделю/месяц, график по дням, CSV. Московское время, без аналитики товаров.
- Сохранение опубликованного календаря и фото офлайн. Первый вход требует сети. Сохранённые данные могут устареть; видна дата обновления.
- PWA с локально собранными зависимостями и шрифтами системы; CDN для JS не нужен.

## Локальный запуск

Node.js 22+, `npm ci`, `npm run dev`. Сборка: `npm run build`; результат `dist/`. Тесты: `npm test`. Браузерные проверки: `node tests/browser.mjs` с установленным Chromium; проверка сама запускает локальный сервер на 4173 (`npx playwright install chromium`).

Конфигурация содержит только общедоступный publishable key и legacy anon JWT для JWT-проверки Edge Function. Секретных service_role ключей и паролей в репозитории нет.

## Вход и первое наполнение

Админка: корень сайта + `?admin=1`.

1. В Supabase → Authentication → Users → Add user → Create new user создайте администратора со своей почтой и паролем. Пароль задаёт владелец, не храните его в репозитории.
2. Скопируйте UUID созданного пользователя и выполните в SQL Editor `insert into public.admins(user_id) values ('UUID');`.
3. Войдите в админку, создайте период, загрузите реальные фото и проценты скидок, сохраните.
4. Откройте «Предпросмотр», проверьте даты/упаковки, нажмите «Опубликовать период».

Создание аккаунта без записи в `admins` не даёт никаких прав. Открытой регистрации в интерфейсе нет. Даже если кто-то самостоятельно зарегистрируется через Auth API, ему доступны только опубликованные данные.

## Размещение

`dist/` можно разместить на любом HTTPS-хостинге статических файлов. Вход в админку использует пароль и не требует email redirect. Бесплатный GitHub Pages требует публичного репозитория в обычной учётной записи. Репозиторий публичный, GitHub Pages включён с разрешения владельца. Сайт: https://nemozhenkov-cmd.github.io/chizhik-calendar/ . Админка: https://nemozhenkov-cmd.github.io/chizhik-calendar/?admin=1 . Для первого входа требуется создать пользователя администратора по инструкции выше.

Для GitHub Pages: Settings → Pages → Deploy from a branch → main → /docs. В репозиторий включена готовая сборка в `docs/`; после изменений выполнить `npm run package` и сохранить обновлённую папку `docs/` в GitHub.

Если меняется домен сайта, добавьте его origin в `supabase/functions/visit/index.ts` и повторно разверните функцию. Настроенный origin: `https://nemozhenkov-cmd.github.io`.

## Как считаются посещения

Одна вкладка использует случайный идентификатор 30 минут. После этого создаётся новый визит. В другой вкладке может считаться ещё один визит. Это не уникальные люди. Дата и дедупликация вычисляются сервером по Москве. Raw IP не записывается в таблицу: используется HMAC с солью, меняющейся ежедневно. Счётчик ограничивает приём 100 визитами с одного IP в сутки, поэтому общий IP мобильного оператора может приводить к недосчёту. Боты, блокировщики и отсутствие сети также влияют. После первого входа администратора устройство исключено из счётчика локальным маркером; очистка данных браузера сбрасывает маркер. Переход по ссылке «Сайт покупателя» из админки исключён из учёта.

RLS запрещает покупателю читать статистику, список администраторов и черновики или менять данные. Функция `visit` проходит JWT-проверку шлюза, проверяет origin и формат запроса, а записывает только визиты. Фото находятся в публичном bucket: сами адреса фото не являются секретом, в том числе фото черновиков. Не загружайте приватные документы.

## Эксплуатация

Сохраняйте резервную копию исходников и периодически экспортируйте таблицы в Supabase. Бесплатный тариф Supabase имеет квоты и может приостанавливать неактивные проекты. Доступность в российских мобильных сетях и при «белых списках» не гарантирована. Проверьте реальный адрес на Wi-Fi и мобильной связи перед печатью QR.

Оригинальные изображения товаров не перерисовываются: загрузка только уменьшает фото до 1000 px и сохраняет WebP. Демонстрационный `brand/sample-tan.jpg` — исходное изображение из каталога X5, используется только в локальных тестах, не публикует акцию.

Логотип: https://logo-teka.com/chizhik/ (готовый вектор, не новая генерация). Маскоты скопированы без изменения из `nemozhenkov-cmd/sroki-bandy/public/brand`.

## Установка и уведомления о календаре

При первом открытии на устройстве появляется окно с предложением установить приложение и подписаться на уведомления. Оно не повторяется после закрытия; открыть его снова можно кнопкой «На экран телефона и уведомления». Системные запросы браузера запускаются нажатием кнопок пользователя. На iPhone/iPad (16.4+) сначала требуется добавление на экран «Домой» и запуск оттуда; при первом открытии установленного приложения предложение подписки показывается отдельно.

В админке под товарами периода находится блок «Сообщить о новом календаре». После публикации периода нажмите «Уведомить подписчиков», проверьте текст и подтвердите «Отправить всем подписчикам». Рассылка отправляется подписанным устройствам, не всем посетителям сайта. Одна рассылка на период защищена от повторного нажатия и повторной отправки. Число подписчиков, принятые push-сервисами сообщения, очередь и ошибки отображаются в блоке. При нажатии на сообщение открывается соответствующий период.

Очередь хранится в БД. Функция `calendar-push` обрабатывает её сразу и плановым заданием `calendar-push-worker` каждую минуту: закрытие админки не прерывает рассылку. До 4 пакетов по 24 сообщения за проход (новый пакет начинается только в первые 45 секунд), по 6 параллельных запросов, до 3 попыток на временные ошибки. Если push-сервис уже принял сообщение, но обработчик был остановлен до отметки в БД, повторная доставка технически возможна; tag календаря объединяет такие уведомления там, где браузер это поддерживает. Кнопка не создаёт новую кампанию для того же периода.

Ключи VAPID генерируются на сервере и хранятся в закрытой RLS-таблице `push_config`, доступной только service_role. В публичном коде нет приватных ключей. Подписки защищены случайным 256-битным токеном устройства, сервер хранит только его SHA-256. Админские запросы дополнительно проверяются Supabase Auth и таблицей `admins`. Покупатель может отключить свою подписку в том же окне; устаревшие подписки удаляются после 404/410 от push-провайдера. Произвольные URL для отправки запрещены: допускаются только HTTPS-адреса известных браузерных push-провайдеров, перенаправления запрещены.

На новом проекте после основной схемы применить `supabase/push-setup.sql`, развернуть `supabase/functions/calendar-push/` с `verify_jwt=true`, затем адаптировать и применить `supabase/push-scheduler.sql` под свой проект и публичный anon JWT. Настройки здесь относятся только к `saeywokxwhrvfrwdrmjx`. Worker-token не хранится в коде задания: он читается из закрытой таблицы на сервере.

Проверки: `npm test` (включая фильтрацию адресов, формат ключей, Web Push encryption и обработчики Service Worker); `node tests/push-browser.mjs` (окно первого входа, разрешение по нажатию, отказ, iPhone, отключение и подтверждение рассылки на фикстурах); `node scripts/verify-push-backend.mjs` (реальная защита API, без отправки); `tests/push-queue.sql` — транзакционная проверка с откатом, без контакта с push-провайдерами. Для проверки реальной доставки нужна подписка физического телефона и отправка администратором: доступность браузерных push-сервисов в российских сетях, настройки ОС, энергосбережение и доставка вне сети не гарантированы. Это относится и к ограничениям мобильного интернета по «белым спискам».

### Персональные напоминания о товарах

В карточках будущих акций есть колокольчик «Напомнить об акции». Он сохраняет выбор для текущего устройства; повторное нажатие отменяет напоминание. Отправка запланирована на 18:30 Europe/Moscow накануне скидки. После этого времени новое напоминание на эту дату поставить нельзя. Пользователь должен разрешить Web Push; на iPhone приложение нужно установить на экран «Домой». Отключение push удаляет связанные напоминания. Между разными устройствами выбор не синхронизируется.

Закрытая таблица `push_reminders` и RPC из `supabase/reminders.sql` доступны только service_role. Edge Function проверяет владение подпиской по случайному токену устройства. Уже существующий минутный worker обрабатывает персональную очередь, использует аренды и максимум три попытки; отменённые, удалённые и снятые с публикации предложения не отправляются. При изменении даты время пересчитывается. Время доставки зависит от сети/ОС; TTL заканчивается в полночь перед днём акции, чтобы напоминание «Завтра» не приходило позже.

Напоминание «Завтра дешевле!» содержит название, подпись и процент; открывается конкретная карточка опубликованного товара через `?period=…&offer=…#calendar`. Новый календарь: «Чижик принёс новые скидки!». Фирменная иконка и монохромный badge дополняются картинкой товара/маскота на поддерживающих браузерах. Компоновку и шрифты задаёт ОС; картинка является необязательным дополнением. Старые уже отправленные уведомления не изменяются.

Проверки: `npm test`, `node tests/browser.mjs`, `node tests/push-browser.mjs`; `tests/reminders-queue.sql` выполняется целиком с rollback и не отправляет push. `node scripts/verify-push-backend.mjs` проверяет закрытые таблицы и отказы в доступе без подписки/рассылки.

### Любимые товары

Третья вкладка покупателя — «Любимые». Сердечки в карточках и в подробностях сохраняют товар на текущем устройстве (localStorage `calendar-favorites-v1`, до 200 товаров). Регистрация и разрешение push для списка не требуются. Сохраняются исходные фото, название и объём; опубликованные предложения связываются по `product_id` и сортируются: сегодня → ближайшие → пока без акций. После очистки данных/смены устройства список собирается заново.

При активной push-подписке выбор синхронизируется с закрытой таблицей `push_favorites` по токену владельца устройства. При запрете push список остаётся локальным. Версия снимка защищает сервер от запоздавших сетевых ответов/повторов; удаление сердечка удаляет подписку на этот товар. Разрешение уведомлений запрашивается только явной кнопкой, а не нажатием сердечка.

Новая публикация календаря атомарно записывается в `calendar_publications`. Минутный worker объединяет совпадения в одну запись `favorite_deliveries` на устройство/период и перед отправкой повторно проверяет избранные, публикацию и будущие даты. Повторная публикация того же периода не создаёт второе сообщение. Добавление в любимые после публикации не рассылает старый календарь задним числом. Общая административная рассылка и напоминание накануне остаются самостоятельными функциями.

Каталог `products` и `product_aliases` сохраняет идентичность между периодами. В редакторе администратора для повторной акции выбирайте «Товар из каталога»; для другого вкуса/объёма — «Новый товар». Новые записи без выбранного ID автоматически связываются только по нормализованному названию и подписи, без приблизительного сопоставления разных упаковок. Две подтверждённые упаковки TAFO Deluxe 3 слоя/100 шт. из октябрьского и ноябрьского коллажей объединены при импорте.

Дополнительные проверки: `node tests/favorites-browser.mjs` (включая отсутствие разрешения, локальное сохранение, офлайн, 320px и sync); `tests/favorites-queue.sql` (только transaction + rollback, без реальных сообщений).
